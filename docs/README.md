# What is in `docs/`, and where a new document goes

**The directory says what a document is.** The filename does not: a plan need
not have `PLAN` in its name, and a handoff or a set of notes can be a plan, a
design record or maintained reference. Read the directory, not the name.

| directory | what is in it | read it as |
|---|---|---|
| `docs/` | how the system works **today** — instructions, contracts, maintained reference | true of the tree you have checked out |
| `docs/plans/` | proposed or half-finished work | a **proposal**; the tree does not do this yet, or does part of it |
| `docs/plans/completed/` | the design record behind something that shipped | **how it got there**, not what it does — SPEC.md is what it does |
| `docs/history/` | superseded, or a record of a moment that has passed | true of **no** tree you can check out |
| `docs/reports/` | a measurement taken at a point in time | true of the tree it was **taken on** — quote it with its date and its box |

`docs/INDEX.md` lists every document under those five headings. It is
generated by `tools/os88index.py`, which takes the classification from the
path, and `--check` runs in every `make`, so a moved file fails the build
until the index is regenerated. Moving a file is the whole of reclassifying
it; there is no second list to keep.

Images a document embeds live beside it (`docs/screenshot.png`,
`docs/runcpm/`). They are not indexed.

## Where a new document goes

- Describes what the code does now, or tells someone how to do something →
  **`docs/`**. It has to stay true, and it changes in the same commit as the
  code that makes it false.
- Proposes work, or records work that is part done → **`docs/plans/`**.
  Handoffs are plans: a handoff is a plan addressed to whoever picks it up.
- Its work has landed → move it to **`docs/plans/completed/`**, in the commit
  that lands the work. A finished plan left in `docs/plans/` reads as an open
  commitment. Fix the file's own status line in the same move: a document in
  `completed/` whose first paragraph still says "not started" contradicts the
  directory it is in.
- Reports a MEASUREMENT rather than a design — how long something takes, what
  it costs, what a sweep found → **`docs/reports/`**. It is not maintained and
  is not meant to be: it says what was true on one tree on one box, so it
  carries its date, its commit and the machine it was taken on, and a later
  measurement is a NEW file rather than an edit to this one. A report whose
  numbers have driven a change should say which.
- Superseded, answered by something that replaced it, or a report of a bug
  that no longer reproduces → **`docs/history/`**, if its reasoning still
  earns the space: a study that ruled something out is what stops that thing
  being re-derived. A document that carries nothing of the kind is deleted,
  not filed. Delete with `git rm` and fix every referrer (`grep -rn
  <basename>` over the tree, CLAUDE.md, README.md, `tools/`, `tests/` and
  the Makefile included).

**A REGISTER also lives in `docs/plans/`** — `LAST-DROP-BYTES.md` and
`LAST-DROP-PERF.md` are menus of things the machine could do, each priced,
each deferred indefinitely. They are outstanding forever by design and are
finished only when empty, which nobody is working towards. They are filed as
plans because a row is a proposal, not a description of the tree; do not read
one as a commitment.

**A plan with some waves built and some not stays in `docs/plans/`** — that is
what "half done" means and where a reader should find it. Split it into a
completed record and a remaining plan only when the two halves have stopped
being one argument; when you do, each must name the other in its first lines
(`KERN-SMALL-CUT-PLAN.md` and `completed/KERN-SMALL-CUT-BUILT.md` are the
worked example).

## What does not move

`SPEC.md`, `PERFORMANCE.md` and `REDRAW-SPEC.md` are at the repository root and
stay there. A bare `§` anywhere in this repository means SPEC.md.

## Citing one

Cite a document by its **full path and a section number** —
`docs/plans/completed/TEXT-PLAN.md §4.4`. `tools/checkdocs.py`, which every
`make` runs, resolves the document by its **basename**, so a citation survives
a move between these four directories — and so **two documents may not share a
basename**: the resolver keeps one and silently checks every citation of the
other against it. It then checks the section number against the file it
names: a number that is not a heading there fails the build. A document with
no numbered headings at all (docs/TESTING.md) is skipped rather than checked,
so a citation into one proves nothing.
