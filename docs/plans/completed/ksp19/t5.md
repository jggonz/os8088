## TAKEN

### T5 - the table renumbered once, every rare cell an index

* **96 published door cells.** Every six-byte rare cell left the table and
  became an `RDPUB kind, routine, NAME` line in `rd_tab`, in kind order (RS
  42, RCS 18, RX 7, RCX 19, RN 10), the three kern_mega-only cells
  (`OSAPI_XMEM_SEL`, `_XMEM_RUN`, `_MEM_CODESEL`) and kern_small's two inline
  refusals (`OSAPI_FS_OP`, `_VOL_CHECK`) among them. The table holds only hot
  shapes now: 77 cells, 0x0010..0x0233 (was ..0x046D), 547 bytes.
* **One index space** (SPEC.md 20.3.4): `rd_tab` = the kernel's own P4
  entries (27 on kern_big/emu/mega, 16 on kern_small) at absolute 0..RD_P-1,
  then the published block in one fixed order on every kernel. A site carries
  the published index; the door does `add bl, RD_P` first; `KDOOR` emits
  `(rix - RD_P) & 0xFF`. A kernel with no body holds the index with a
  refusal entry: `RDREF` to `api_refuse` (kern_big/emu: XMEM_SEL/RUN, 5 bytes
  `.text`), kern_small's `xm_copy` (already those bytes) for XMEM_SEL/RUN and
  FS_OP, and `.cold` `api_refusec` for kern_small's VOL_CHECK (RCS range).
  MEM_CODESEL off kern_mega is a 5-byte `.text` body. `t_api_abi --all`:
  identical indices on all four (3,341 checks).
* **The bracket's cells** (door.md rule 1). Kept as table cells, in hot
  shapes, so all five old bodies could go: `OSAPI_XMEM_CAPS`, `_FSX_SPK`
  XCELLs (neither reads ES); `OSAPI_SEG` an XCELL to `api_seg` (8 bytes
  `.text`: `mov bp, osapi_seg / push cs / call api_far / ret`); 
  `OSAPI_FILE_READ_SEQ` the one **NCELL** (XCELL shape jumping to `api_nc`,
  which calls `api_nb`, the N body the door's RN kind calls too -
  `API_RN_DSOFF` stays 10). **Taught the bracket's door instead** for the
  three kept-as-is runs: `OSAPI_SND_CAPS`, `_FONT_GLYPHS`, `_FSX_MODE` are
  the published block's first three (`RD_RK`), and `fsx_rdownf` writes
  `RD_P + RD_RK` over the bound in place of 0 (0 bytes). door.md's list missed
  FSX_MODE (rmk_7's run). Side effect, noted: in the bracket the kernel's own
  27 P4 indices answer too; no code the bracket runs reaches one.
* **Deleted**: `api_rx`'s head, `api_rxc`, `api_rsc`, `api_rs`, `api_rn`,
  every `OSAPI_R*` macro, the per-cell RARECNT counters, five `cw_X equ
  apic_X` aliases and the `apic_` labels of moved cells. 34 kernel/module
  far calls became `KDOOR` sites (toast_show x15, wm_show, wm_minsize,
  wm_title_set, wm_grow_paint, wm_flag, osapi_fs_op, fpg_stepb, wm_front,
  inst_minimize, wm_top, xm_alloc, xm_free; CMZ_/CLO_ equs became
  `%define`s of the routine).
* **V7**: `OSAPI_GFX_DESK` is a SLOT (kern_small: `gfx_fill_gray`). **V2**:
  the YSLOT stays hot, unchanged.
* **SDK**: a door cell's `%define` says `OS88_DOOR` (defined nowhere, so a
  non-`call` use fails); the generated block re-expands it `__OSAPI_RARE
  <index>`; `OS88_RARE_DOOR` is 1; the arm is `int OS88_RARE / db %1`
  (OS88_RARE_VEC dropped). `os88cells.py`: NCELL decode, `kernel_doors()`
  from `rdp_<NAME>` equates and `rd_tab`, blocks/`stale()` on (index,kind),
  far-call gate = the mid-cell rule (a door cell has no offset to refuse).
  Hot cells renumbered by script (order-preserving map old->new from the
  decoded table); 256 hot and 292 door citations rewritten tree-wide (door
  ones to "a door cell"); `os88index` shows `door 0xNN`.

### A DEFECT FOUND - the door ate the caller's flags

P4's door did `push [bp+6] / popf` FIRST, then its range compares wrote CF/ZF
before the body. Bodies that PRESERVE flags (`OSAPI_MENU_SET`,
`_WM_PREFER`, SPEC.md 20.3) then returned the door's flags: Note Pad's entry
carries `OSAPI_WM_CREATE`'s CF across both and its window never opened, and
DOS.O88 said "Not enough memory" for every program (`dosvec`/`dosdir` red).
P4's kernel-private callers read none. Fix: `push word [bp+6]` before the
compares, a `popf` as the first instruction of each kind and of `.ref`
(+5 bytes; cycle-neutral, IF back ~60 clocks later). Found by tracing every
door hit under MartyPC (scratch `trace2.py`). SPEC.md 20.3.4 step 1 says it.

## REFUSED / WANTS THE OWNER

* **Serving the bracket's twins through the door** (XMEM_CAPS, FSX_SPK,
  READ_SEQ, SEG): the twins are far-entered `retf` bodies in the service
  area; a door adapter (frame + `retf 2` + segment) costs more than the four
  hot cells (+1 each over a rare cell, +8 `api_seg`). Recorded.
* **A wire fence on door indices**: not taken - a kernel lacking an index
  REFUSES it (CF=1, AX=1), so no level is needed, and the scan cannot fence
  (C64/PIXELSTEIN 3D/Skies data spell `CD 81 FF`). `door_top()` reports only.
* Nothing for the owner.

## WANTS AN ABI BREAK (found, not taken)

* Drop `add bl, RD_P` (-3 bytes x 4 kernels, -12 clocks a door call): put
  the kernel's own entries in a sixth range AFTER RN (+5 door bytes, and the
  P4 calls - `inst_win_owner` 97 a session - pay five compares, ~+100
  clocks). Smaller by nothing; slower on a kernel-private path. Not taken.
