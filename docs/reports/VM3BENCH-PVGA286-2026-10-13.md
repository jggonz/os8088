# Write mode 3 on the owner's 286: VM3BENCH, and what it prices

**A measurement, not a description.** VM3BENCH (`make vm3bench`, built at
`video-palette`'s commit adding it) run by the owner on 2026-10-13 on the
`286-fast` machine - an AMD 286, 16 MHz, Paradise PVGA1A on the board -
saved as VM3BENC1.TXT. The projection below is a host-side replay on a
4-core Xeon container of the same day. True of that card and that tree.

## The bench, per 2,000 bytes onto mode 12h

| row | us | us a byte |
|---|---|---|
| write mode 0, `rep movsb` | 2,296.7 | 1.15 |
| write mode 0, `lodsb`/`stosb` loop | 4,225.9 | 2.11 |
| write mode 3, `rep movsb`, no read | 2,295.7 | 1.15 |
| write mode 3, `lodsb`/`and [di]` loop | 6,393.4 | 3.20 |
| write mode 3, `lodsb`/read/`stosb` loop | 6,494.9 | 3.25 |
| `out dx, ax` to 3CEh (a set/reset) | 3,767.5 | 1.88 each |
| `rep movsb` read from the screen | 2,351.1 | 1.18 |

**Both checks OK**: the card writes the set/reset colour to the masked
pixels on all four planes, by AND and by read-then-store. A read costs what
a write does; a write mode 3 store is 1.1 us more than a store in the same
loop, 2.8 times a byte of a block move. Read mode 1 with Color Don't Care 0
makes the read return FFh, so the AND form is the cheaper.

## What it prices: Gas Gas Gas 89-99 s, GASSHOTX's settings

The records of the 0-band file (docs/plans/VIDEO-PALETTE-PLAN.md 10.5) were
replayed with the `286-fast` profile's own table, and each byte written by
more than one plane-group sub-record repriced as write mode 3 stores - one
AND-store (3.20 us) per NEW colour among its changed pixels, one OUT (1.88
us) per colour in the frame - in place of its plane stores at the slice
rate (1.227 us a byte):

| bytes rewritten in write mode 3 | share of bytes written | mean decode, of a period | worst frame |
|---|---|---|---|
| none (today) | - | 25.9% | 51.6 ms |
| every byte with more than one group | 65.4% | 34.3% (+32.8%) | 74.0 ms |
| only a byte some state of which shows a pixel > 25 dE from both its old and new colour | 14.1% | 28.6% (+10.6%) | 63.1 ms |
| ...> 40 dE | 12.2% | 28.3% (+9.4%) | 61.4 ms |

The selective rows show no wrong colour on the glass by construction (every
byte that could show one is written in one store a colour), against the
0-band file's 288 a frame and 24 bands' 17 at +22% of data. The data a
rewritten byte costs - a mask a colour where today it is a byte a plane
group - is not priced here.
