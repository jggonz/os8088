# Apps size pass 1 — measured 2026-10-10

**A MEASUREMENT** (docs/README.md): true of the trees below and of no other.
A later measurement is a new file.

The first dedicated size pass on application packages. Kernel passes 1-12 and
the system-side pass (docs/reports/SYSTEM-SIDE-SIZE-P1-2026-10-04.md) had been
done; individual packages had only had their own size work. This pass took
the first eight entries of a raw `ls apps/`: 1942, apple2, arkanoid, artful,
audio, browser, c64, calc. (`cc/`, the C SDK, is ninth and belongs to the next
batch.)

- **Tree**: branch `apps-size-1`, cut from `elendilon` at `0371d27`. "Before"
  is `0371d27` built in this container; "after" is `apps-size-1` with all eight
  packages merged (`1f5703e`).
- **Box**: the 4-core cloud container this session ran in. Every number below
  is counted, not timed, except where a row reports guest cycles or frame
  times off MartyPC's 4.77MHz 8088.
- **Method**: one agent per package, each in its own git worktree, stretch
  target 30% of image+bss, with "no feature removed, hot paths not slower,
  shared includes / kernel / drivers off-limits - record the win instead".
  Each branch was merged after its own rows passed; the merged tree was then
  built and its fast tier run (61/61), and every package's rows run together
  (Coverage, below).

## The table

`image+bss` is the per-instance claim (SPEC.md 20.1). `file` is the bytes of
`build/<pkg>.o88` (LZ4 `'CZ'` for assembly packages; the C packages' images
ship uncompressed - see C.10 below). The runtime-claim column is what the
package takes from the heap while it runs, which `image+bss` does not see.

| arkanoid | 7,690 | 6,476 | -15.8% | 5,740 | 5,262 | none |

| audio | 42,872 | 21,698 | **-49.4%** | 11,120 | 10,935 | unchanged (32 KB ring; 17 KB speaker ring) |

No kernel, driver or shared-include byte moved.

### Where the big numbers came from

- **audio**: the 16 KB `ap_scratch` bounce is gone - each refill reads
  straight into the 32 KB look-ahead ring (a heap claim, 512-aligned by guard
  6b), which also drops a ~16 KB `rep movsb` per gulp. Buffers never live on
  the same track now share storage (SPEC.md 86.5.2, 86.12).
- **artful**: the 9 KB 4bpp strip and its expander are gone from the default
  build; a colour code-span line is runs of `OSAPI_GFX_BLIT1` bands with their
  own pen (SPEC.md 46.4.12). The `NOATBLIT1` knob keeps the old path. The undo
  arena grows on demand (46.6.3).
- **1942**: the three runtime claims are sized at assembly time from what is
  read into them; generated data (latch lists, stage events, note streams,
  splash labels) repacked by 1942's own generators (SPEC.md 101).
- **browser**: a fetch claims only its source buffer, and the document, line
  and link buffers are claimed after the page has arrived, sized from it
  (SPEC.md 71.14; docs/HEAP-CLAIMS.md).
- **apple2**: the RAM claim stops at the soft-switch boundary (the core's
  scratch page moved `$CF00` -> `$C100`), and the ROM carve gives back the
  character generator once it is decoded (APPLE2-SPEC 1.1, 1.5, 3.1, 3.3).
- **calc**: one register save for the whole engine, the 29-rect table replaced
  by one computed rect, the shared About card (SPEC.md 65.10.3).

## User-visible changes

- **About cards**: arkanoid, browser and calc now use the standard
  `os88ui_about` card. Line pitch is the system's 12 px, so text moves a pixel
  or two; text draws in one opaque pass. Browser's private card had drawn
  without a clip region (a defect, below).
- **artful under memory pressure**: undo depth is no longer reserved up front.
  If other programs fill the heap after the editor opens, undo history can be
  shorter than today's 24 KB; the oldest entries drop, as when undo already ran
  out of room.

## Defects

### Fixed

- **audio**: every track's end showed "Cannot read the file" (the
  end-of-data test fell through into `.ioerr`), and in a speaker playlist it
  then showed during the next track. Now asserted by `tests/apspk.py --card`.
- **audio**: the speaker's fractional step overran the 2 KB `apd_out` (2,354
  bytes needed for 44.1 kHz -> 4,800 Hz; 2,049 for 44.1 -> 5,512 on either CPU),
  corrupting PCM output or the parser's state including the file name.
- **arkanoid**: a redraw flag set by the game loop during a full repaint from
  the paint / credits-dismiss paths was dropped; a brick broken during a whole
  wall redraw stayed drawn.
- **browser**: every page was laid out twice on load; the private About card
  drew without a clip region; a raw control byte in a link address went into
  the HTTP request line; four `br*` tests read state before the page loaded
  (failing on the baseline - fixed in the tests).
- **artful**: `at_tw` was not clamped, so a text column wider than 640 px
  would have run past the strip.

### Found, NOT fixed

- **calc**: `cal_isqrt` can seed `1<<32` when the scaled radicand reaches bit
  length 63; DX:AX wraps to 0 and `cq_divmod` divides by zero. Predicted for
  `sqrt(720575940)`, not driven on the machine. Baseline behaviour, kept.
- **browser**: a navigation started while the worker is still parsing the
  previous page lets the parse write into a just-freed buffer (baseline).
- **browser**: `brlink` fails 3 assertions on the baseline as on the branch
  (a stale toolbar layout in the test); `tools/os88proxy.py` still names the
  removed `br_lmap` in a comment.
- **arkanoid**: a full repaint fills the side rails and draws them again
  (written twice); the About and credits paths draw the board without a clip
  region (harmless only because the window is in front then).
- **1942sound** (soak row): its adlib and sb legs fail on the baseline at
  `assert driver('sbl_up')[0]==(backend=='sb')`, before any 1942 audio runs -
  shared plumbing in `tests/drmario_audio.py` (`driver_symbols()` /
  `drv_fseg`), so DrMarco's audio test likely fails the same way. 1942's FM
  path (unchanged code) is therefore untested here; the speaker leg passes.

## Missing kernel / library components — the collection

This is the list the pass exists to collect: what a package hand-rolls that
the OS or a shared include should provide, or a shared piece that forces dead
bytes on its includers. Estimates are the reporting agent's, per includer.

### A. The C toolchain (`tools/cc8086.py`, `apps/cc/`) — every C package

Raised by both C agents (apple2, c64) independently. The C packages are
cword, runcpm, c64, apple2, paccman, weave, loom.

| # | what | estimate |
|---|---|---|
| A.1 | **Compare-as-branch peephole**: a compare feeding `&&`/`||`/`?:` is materialised as 0/1 and tested again; it should be one conditional jump. Both agents hand-rewrote sites to nested `if`s as a workaround | apple2 186 sites ~1.7 KB; c64 318 sites ~3 KB; and faster |
| A.2 | **Shift by constant**: `x<<N` is N single shifts; `mov cl,N / shl ax,cl` (N >= 3) or a byte move for 8 | apple2 ~690 B; c64 64 sites ~640 B |
| A.3 | **General peephole**: dead `mov ah,0` after byte stores, post-increment whose value is discarded loaded anyway | several hundred B per large package |
| A.4 | **Identical string literals are never merged**; `label+const` addressing is not folded | tens to hundreds of B |
| A.5 | **`os88thunk.asm` has no per-thunk gate**: every thunk is assembled whether called or not; `cc8086.py` could emit a define per referenced external | apple2 ~1,340 B |
| A.6 | **`os88_memset`/`os88_memcpy` are byte loops**; `rep stosb`/`rep movsb` is smaller and faster | small, every C package |
| A.7 | **No `os88_peek16(seg, off)`** in the C SDK | apple2 hand-rolled one; c64/runcpm loaders likely |
| A.8 | **No `os88_part_shrink(i, keep)`**: the parts carve base is not exposed to C, so a part needed only at load (character generators, fonts, tables) cannot be given back | apple2 3 KB done by aliasing `op_base`; c64's chargen a candidate |
| A.9 | **No way to drop an overlay** once `cc_ovneed` loads it: the claim is held for the session | 4-18 KB (CWORD.OVL 18,565). For c64 the alternative is folding C64.OVL back in, ~1.5 KB net - owner's call |
| A.10 | **No C package's image is ever compressed**: `apps/cc/Makefile.inc`'s `CC_PACKAGE` never passes `$(PKGZARG)`, and `os88pkg.py` refuses `--compress` on a package with parts | disk only, large: c64 image 40,244 -> 23,275 LZ4, ~-14 KB net of disk; apple2 the same shape |

## Wins seen but not taken (summary)

Each agent's list is in its merge commit's branch; the recurring reasons:

1. **Hot paths**: the 6502/6510 cores and composers, 1942's per-sprite tables
   and latch lists, the browser's 8 KB line table and parse staging, artful's
   line table and `at_fontbuf`, audio's ADPCM input bounce.
2. **Features**: browser history (1,280 B), audio's playlist capacity, artful's
   2,048-line ceiling.
3. **Shared includes**: about 1-2.3 KB of every UI package's image is
   `os88ui.inc` (scroll bar, About card, `os88ui_btn`, glyph), off-limits here.
4. **Time**: c64 stopped at the deadline with more code-shape work open (CIA
   state as a struct, `c64_reset_regs` via `os88_memset`, `frame_regs`'
   shifts); apple2 left ~210 compare-as-branch sites for A.1 rather than hand
   edits; browser left four built-but-unverified edits (-48 B) out.
5. **Trades refused**: 1942 deriving its packed splash from planar (27 ms a
   band on the XT) or LZB for the splash (4x decode, breaks the reveal); c64
   moving `c64_paste_feed` into the overlay (31 shim crossings per wake).

## Coverage

Each package ran its own rows in its worktree, listed in its report. The merged
tree (`1f5703e`) then ran `make` (fast tier 61/61) and `make c64 apple2 1942
smallapps`, and the union of the eight packages' emulator rows through
`tools/os88soak.py`: **24/25 ok** in 612 s at lane 4. The one failure,
`apspkcovox`, died in the harness before any audio ran (MartyPC's mouse saw
the double-click's presses 10 ticks apart against a 9-tick window, under four
lanes of load) and passed when re-run alone. The 25 rows: 1942, 1942front,
arkpuwipe, dispapp, dispapps, dispsize, dispmodex, apspk, apspkcard,
apspkcardc, apspkpause, apspkcovox, audhand, btnall, regapp, atmenusu,
c64part, apple2part, appsmall, calcflick, dispcalc, dispcalcx, smalllaunch,
dispbrow, pkgthumb-br. `1942sound` was left out (it fails on the baseline,
above) and the browser's network rows ran in that agent's worktree only.

Not covered by any row, by the agents' own account: artful's new VGA code-line
cycle count and a break-on-purpose run against it; artful `atkey`/`atclip`/
`editmove --app artful`/kern_small; arkanoid's About card on the glass and
kern_small; calc's About card and BLIT1 triangle by eye; apple2's Color NTSC
bracket on a VGA machine and its Load/Save/Paste/About on MartyPC (host
harness only); c64's Copy/Paste and Smart attach on the machine; audio's 44.1
kHz -> 4,800 Hz step on an 8088 (arithmetic only); browser `dispprefer`; 1942's
FM path; the 1942 cartridge build (`N_ROM=1`, no ROM in the tree).

## Process notes for the next batch

- **Agent worktrees were cut from `main` (`95f7e971`), not from the branch the
  session was on.** Seven of eight agents noticed and moved themselves onto
  `0371d27` before changing anything; audio worked on the stale base and had
  to rebase (its first numbers were measured on the wrong tree). The brief for
  the next batch should say "your first command is `git reset --hard
  origin/apps-size-N`" and the coordinator should check every worktree's base.
- **Writes outside the worktree cause permission prompts.** The brief told
  agents to symlink `build/cc` and `build/martypc` into the main checkout and
  some used the session scratchpad; mid-run they were told to keep every write
  inside their own worktree and treat the links as read-only. Put that in the
  brief from the start.
- **`pkill -f "make -j2"` matches every agent's build.** Two agents ran it and
  may have killed another's build at ~20:32. The brief should forbid
  pattern-kills of shared command lines.
