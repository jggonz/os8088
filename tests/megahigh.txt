# tests/megahigh.txt - the OS88_HIGH / OS88_HIGHMEM exemption registry
# (docs/plans/KERN-MEGA-PLAN.md 14.51, 14.52)
#
# On kern_mega two bits of a package's class byte (+15) are the opt-in to
# extended memory (apps/os88api.inc): OS88_HIGH, the region may be loaded
# above 1MB, and OS88_HIGHMEM, its claims of 64KB or less may be too. The
# owner's rule: "opt in is fine but only with a full tier gate. They need to
# except themselves if they want to not opt in, and they need a damn good
# reason to do so."
#
# ONE LINE PER EXEMPTION: <kind> <package>  # <reason>
#
#   high     the package does not declare OS88_HIGH
#   highmem  it does not declare OS88_HIGHMEM
#
# A reason may run on over indented `#` lines below it. tests/unit/t_megahigh.py
# (full tier) is the gate, and the list turns ONE WAY: a line for a package
# that now declares is a FAILURE.
#
# THE BAR. A reason names a concrete thing in the code that breaks above 1MB -
# paragraph arithmetic on its own CS/DS or on a claim's segment, a far pointer
# kept for real mode, an IRQ vector stamped with its own CS, DMA or a BIOS
# call on a claim, a claim over 64KB stepped by segment arithmetic - with the
# place it is and what would retire the line. "Nobody looked" is not one: if
# you looked and found nothing, the answer is the declaration, after running
# the package on kern_mega (docs/BOCHS.md).
#
# NOT HERE, BY CONSTRUCTION: a parts LOADER (its source invokes OS88_REHOME -
# csload, wdload, scload, dosload, pxstein) is never asked for `high`, and is
# asked for `highmem` only when its own source claims. The gate's docstring
# says why; its program part is a package of its own and is checked as one.

# --- high --------------------------------------------------------------------

high apps/waverack/waverack.asm   # ITS OWN DS COMPARED AS A PARAGRAPH: wc_myslot
    # (apps/waverack/wrrec.inc) finds the instance's slot - the recovery
    # markers' name for the recorder (SPEC.md 123.7) - as the
    # OSAPI_SYS_SNAPSHOT record whose SSI_SEG equals DS, a real-mode paragraph
    # comparison. WaveRack is kern_big only (SPEC.md 123.13; no PKG_MEGA arm)
    # and has never run on kern_mega. Retired by a snapshot field that names
    # the caller's own instance, or a run on kern_mega showing SSI_SEG is DS.

# --- highmem -----------------------------------------------------------------

highmem apps/waverack/waverack.asm   # A CLAIM STEPPED BY PARAGRAPH: wt_hoff
    # (apps/waverack/wrxport.inc) addresses the playback HOLD - one byte a
    # frame, more than 64KB for a long region - as [wt_hseg] plus the offset
    # >> 4, segment arithmetic on a claim's segment; and the record and play
    # rings are OSAPI_MEM_CLAIM_DMA_HI claims handed to SOUND.DRV for DMA.
    # Never run on kern_mega (kern_big only, SPEC.md 123.13). Retired by
    # OSAPI_MEM_HUGE's step for the hold (KERN-MEGA-PLAN 14.67) and a run on
    # kern_mega.

# --- both --------------------------------------------------------------------

high apps/win16/win16.asm       # IT REFUSES UNDER PROTECTED MODE: w16_pmcheck
    # (win16.asm) toasts and ends at entry when OSAPI_CPU_INFO answers
    # CPU_F_PM (SPEC.md 124.1, WIN16-PLAN D6), because what it runs is a
    # real-mode Windows program whose loader writes PARAGRAPHS into its code
    # (w16load.inc's fixups) and whose GlobalLock hands it segments
    # (w16mem.inc). It has no kern_mega arm and none is on the megaapps disks.
    # Retired by a protected-mode WIN16 (Windows 3.x standard mode, the plan's
    # R3), which would hand out selectors instead.
highmem apps/win16/win16.asm    # THE SAME REFUSAL, and the claims are the same
    # paragraphs: the program's segments and its global heap are addressed as
    # base + paragraph offsets by the fixups and by GlobalAlloc's arena walk
    # (w16_garena, GH_SIZE in paragraphs). Retired with the line above.
