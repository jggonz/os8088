VIDEO PLAYER - 286 DECODE BENCH
===============================

One question: how fast does THIS 286 decode a video
frame? The encoder's "286-speeddemon" profile (then
"286-vga") was measured on 86Box's 286; this floppy
measures a real one, and
what it reads becomes that machine's own profile.
The frames are the same synthetic set the 86Box 286
and 486 profiles were fitted from, so the three
machines can be set side by side.

Nothing here writes anything but its reports, on
THIS floppy. Leave it write-enabled.

PLEASE NOTE THE MACHINE: CPU and clock, the video
card and its BUS (8 or 16-bit ISA), and whether the
BIOS shadows the video ROM.

HOW
---
1. Boot this round's os8088 system floppy.
2. Put this disk in B: and open it.
3. VIDBENCH.O88, press R. Screen garbage while it
   runs is expected - it is drawing the frames. The
   report is saved here as VIDBENCH.TXT.
   CLOSE THE WINDOW before the next one.
4. Optional, with a Sound Blaster: VIDSND.O88, R
   -> VIDSND.TXT.

Bring the .TXT files back (or photograph every page:
Space / PgDn / PgUp page through the results).

WHAT MATTERS IN VIDBENCH.TXT
----------------------------
  the raw rows    8,000 bytes to the screen and to RAM,
                  read from the screen, the 12h store
                  and the latch copy: the CARD's speed.
  every frame     "nat scr" is the player's own decoder
                  drawing it. OK/BAD per frame: BAD and
                  the timing does not count.

VIDDISK.O88 (X, E, R, W, C, L) and VIDEOD.O88 - the
player with the long info card - are here too.

LOADALL: VIDDISK.O88, PRESS L
-----------------------------
docs/plans/LOADALL-PLAN.md section 8. Whether this
286 can read and write its extended memory IN PLACE
with the undocumented LOADALL instruction, and what
that costs. Needs memory above 1 MB. Under a minute.
The report is saved here as VDLALL1.TXT - each run
takes the next number, VDLALL2.TXT and on.

It READS the hard disk (the IDE drive at 1F0h, from
cylinder 20, as C does) and writes nothing to it.

IF THE MACHINE FREEZES at "probing LOADALL": reset,
boot again and press M instead of L - the same run
with the one byte of the table nobody has seen work
on a real chip changed. Say which key froze.

If you can, run it a SECOND time with Tracker or
MIDIRack playing through the Sound Blaster in the
background, and say whether the sound broke up, and
which numbered report that run was.

WHAT MATTERS IN VDLALLn.TXT
  LOADALL                ran, or TRAPPED (not usable)
  caches, below 1 MB     ok, or nothing below runs
  A20 before / after     open or SHUT
  32K read in place      ok, or nothing below counts
  ...and 1 KB off        must say "differs"
  32K written in place   ok
  a borrow, no work      what one use of LOADALL costs
  LOADALL / XMEM_COPY    the same copies both ways
  read 32K above / below whether memory past 1 MB is
                         slower than below it
  64 sectors into XMS    ok: the disk read straight
                         into extended memory
  64-sector cmd rows     plain against into XMS
  borrows of 1 .. 8      how many sectors the drive
                         hands over without a pause
