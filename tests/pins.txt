# tests/pins.txt - the PIN registry (docs/plans/NO-PINNING-PLAN.md 4)
#
# A heap claim is born PINNED (SPEC.md 66.2) and a pinned claim is a WALL: free
# memory either side of it cannot be joined. The owner's rule
# (NO-PINNING-PLAN 0) allows three reasons and no other:
#
#   M  an on-demand kernel MODULE (MEM_K_MOD, SPEC.md 2.8) - temporary
#   D  a DEVICE is armed to write into it: DMA, int 13h, an ISR's ring
#   C  in use RIGHT NOW: claimed and freed inside one callback, command or
#      call, or pinned only across a call holding its segment (a file call's
#      ES:BX, an fsx bracket)
#
# ...plus three that are not pins at all and one that is a debt:
#
#   B  a BOOT ceiling claim: top-down, before the first desktop frame, never
#      freed - everything later stacks under it (NO-PINNING-PLAN 2.2)
#   S  shed by design: a purgeable cache the compactor DROPS (6.2, 6.4). A
#      kernel MEM_P_* claim is accepted with no line at all
#   X  another reason, and a very good one - 60 characters at least
#   N  NO VALID REASON YET. Pinned today where the rule says it should move;
#      every N line is a FINDING for the owner, and the gate prints the count
#
# ONE LINE PER PINNED CLAIM: <bucket> <file> <key>  # <reason>
# A reason may run on over lines that start with spaces and a `#`.
#
# THE KEY is what tests/unit/t_pins.py names the claim by: the WORD its
# segment is stored to (`np_stgseg`), a kernel claim's TAG (`MEM_K_COPY`), a
# C lvalue (`func:var` for a local), a parts row (`op:carve`, `op:PART`), or
# `@routine` when nothing names it. Run `python3 tests/unit/t_pins.py --list`
# for every site and its verdict, `--seed` for a line to start from.
#
# THE LIST TURNS ONE WAY: a line whose claim now declares FAILS, and so does a
# line whose key no longer claims. A C line must say what call or bracket it
# is confined to, a D line what device is armed on it. The runtime half,
# tests/pinsrt.py, reads mem_tab back on MartyPC and holds kernel tags to the
# same buckets.
