# tests/cswrites.txt - the CS-write registry (docs/plans/KERN-MEGA-PLAN.md 2.4)
#
# Real mode lets code treat its own segment as data: `mov [cs:x], ax` writes
# through CS, and `push cs / pop ds` makes DS the code segment. 286 PROTECTED
# MODE allows neither. A code segment is never writable, and DS loaded from
# CS is read-only, so both fault on the first store. kern_mega shares most of
# kernel/ with kern_big (KERN-MEGA-PLAN 7), so these are the sites its M1 wave
# converts, and this file stops the number growing until then.
#
# ONE LINE PER FILE: <writes> <pairs> <path>  # <reason>
#
# tests/unit/t_cswrite.py is the gate and says exactly what counts. A file not
# in this list may use neither idiom. A file in it may not exceed its counts,
# and may not fall below them either: a conversion lowers the line, so the diff
# shows the work was done. `t_cswrite.py --list` prints every site with its
# SECTION, which is the M1 worklist.
#
# THE SECTION DECIDES THE CONVERSION, so the reasons below are grouped by it:
#   .boot2         stage 2 of the boot, which runs in real mode before
#                  kern_mega switches. These can stay as they are, if the
#                  switch is placed after them
#   .mod*          an on-demand MODULE writing its own image, which SPEC.md
#                  2.8 allows (docs/plans/MODULE-SELFCONTAIN-PLAN.md). This is
#                  ~390 of the 473 writes, so the CS-write problem is mostly a
#                  module problem, and kern_mega keeps its modules resident
#                  (KERN-MEGA-PLAN 4)
#   .text / .cold  resident code that kern_mega runs in protected mode
#
# A SITE ON AN ARM KERN_MEGA NEVER ASSEMBLES IS NOT COUNTED - inside `%ifndef
# KERN_MEGA`, or the `%else` of `%ifdef KERN_MEGA` - because that is real
# mode's own spelling of something kern_mega does another way, which is what a
# conversion leaves behind. So these counts are what kern_mega STILL gets
# wrong, and every line of `.text`/`.cold` below that is not a knob is a #GP
# on a real 286 - and QEMU will not show it, because QEMU does not enforce
# a code segment's read-only bit (KERN-MEGA-PLAN 9).
#
# CONVERTING A MODULE: `push cs` becomes PUSH_CSDATA and `op [cs:x], ...`
# becomes `CSDO op [CSEG x], ...` (kernel/kernel.asm), both byte-identical off
# kern_mega. CTRL.DRV - ctrl.inc, shutdown.inc, the settings macros in
# driver.inc and desksc.inc's .modc half - was the first, after the Victory
# 286's Control Panel faulted saving SYSTEM.CFG. A `[CSEG x]` outside CSDO
# counts as a write.
#
# THIS IS A RATCHET, NOT A CLEAN GATE, for t_textrules.py's reason. It starts
# at the tree's count, because kern_big is correct as it stands and the only
# failure it can prevent today is a NEW site.
