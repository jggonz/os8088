# tests/megapkg.txt - the kern_mega code a SHIPPED build is allowed to carry
# (docs/plans/KERN-MEGA-PLAN.md 14.66, SPEC.md 20.18)
#
# The owner's rule: "mega specific work that more than trivially increases
# the disk size is gated to mega builds only." kern_mega-only code goes under
# `%ifdef PKG_MEGA` (apps/os88mega.inc) and `make mega` builds that arm onto
# kern_mega's own disks; the shipped builds - every apps disk, every
# geometry - carry none of it. tests/unit/t_megapkg.py (fast tier) is the
# gate: it walks every shipped build's LIVE source (the shipped recipe's
# defines, PKG_MEGA and KERN_MEGA unset, through every %include) and counts
# the code lines naming a kern_mega marker - CPU_F_PM, OSAPI_MEM_CODESEL,
# OSAPI_MEM_SUBSEG, OSAPI_XMEM_RUN, OS88_CODESEL - per FILE, the most any one
# shipped build makes live.
#
# ONE LINE PER FILE: <path> <sites>  # <reason>
#
# A file not listed may have no site. A listed one must have EXACTLY its
# count: the registry turns one way, so gating a site away lowers its line in
# the same diff. A reason says what the site is for and why it is not the
# arm's: the FAIL-SAFE (what keeps a shipped build correct when somebody puts
# the ordinary apps disk in a kern_mega machine), or TRIVIAL (a handful of
# bytes that make the same code right on every kernel - a far call through a
# code alias that OSAPI_MEM_CODESEL answers as DX itself in real mode).
# "It was easier" is not one: bytes on every 8088's disk are the cost.

# --- the fail-safes ---------------------------------------------------------

apps/os88spk.inc 1              # THE SHIPPED BUILD REFUSING THE TIER:
    # os88spk_go's `test ah, CPU_F_PM / jnz .pm`, where .pm is a bare
    # `stc` in a build without PKG_MEGA. The protected-mode ISR copies are
    # the arm's (~900 bytes of each of Audio, Tracker, MIDIRack and the Video
    # Player); without them the real-mode ISRs would store through CS a
    # sample at a time, a fault each, so the PCM tier refuses and the package
    # plays another way. 15 bytes of image (measured on Audio)
drivers/hdd/hdxms.inc 1         # HDD.DRV's fill straight into XMS refused
    # under protected mode (hd_xa_arm): its loaded-base trick loads DS =
    # FFFFh, which is a #GP there (KERN-MEGA-PLAN 14.16). A correctness
    # refusal every build needs - HDD.DRV is one driver on every kernel's
    # disk - and ~10 bytes
drivers/ramdisk/rdstore.inc 1   # RAMDISK.DRV's paragraph fold (rd_fold)
    # in the units the segment's value allows ONLY under CPU_F_PM: whole
    # 128-byte granules for an identity selector, none for an LDT one
    # (KERN-MEGA-MEMORY-PLAN MC8). On a real-mode kernel a segment of that
    # VALUE is an ordinary paragraph, and an unfolded one wraps a transfer
    # over 64KB to the START of the caller's segment with CF=0. A correctness
    # test every build needs, ~10 bytes with its bank
drivers/net/net.asm 1           # NET.DRV's net_norm, the same rule as
    # rd_fold's (KERN-MEGA-MEMORY-PLAN MC8, KERN-MEGA-PLAN 14.69): its
    # one-paragraph fold built a segment off kern_mega's grid. Real mode
    # folds paragraphs exactly as before; the test and its bank are ~25
    # bytes of the image, and NET.DRV is one driver for every kernel
    # under protected mode (um_pmattach): the card's int 33h callback is a
    # real-mode far call into this image, which kern_mega cannot carry back
    # into protected mode, so attaching would hand the BIOS a vector that
    # faults on the first move (KERN-MEGA-MEMORY-PLAN MC7). A correctness
    # refusal - the CH375 path is untouched - and ~8 bytes

drivers/sound/sb.inc 1          # SOUND.DRV's direct-ring ISR reads the
    # 8237's count ONLY under CPU_F_PM (SPEC.md 34.5.2.2), banked at verb 0:
    # on a real-mode kernel the block IRQ lands inside a disk ROM's
    # channel-3 programming (the ST11M's BIOS v2.0 runs it with IF = 1) and
    # its flip-flop clear sent the disk's DMA to the wrong address. A
    # correctness test every build needs - SOUND.DRV is one driver on every
    # kernel's disk - and 23 bytes with its bank

apps/browser/browser.asm 1      # THE BROWSER'S ARENAS AS SELECTORS
    # (KERN-MEGA-MEMORY-PLAN MC7): br_entry banks CPU_F_PM in [br_mega] and
    # [br_docfar], and on kern_mega br_docmap, the parser's br_srcat and the
    # worker's br_take leave their paragraph sums for bound windows (SEG_BWIN
    # + SEG_AIM), the EMS spill copies for SEG_AT (br_at). Without it the
    # shipped Browser is CLOSED by kern_mega (`CLOSED BROWSER 0D`, br_docmap)
    # on the first page it lays out - tests/brmega.py, red on the old build -
    # and with it the region and its small claims run above 1MB (OS88_HIGH,
    # OS88_HIGHMEM). An arm would leave the shipped build refusing to start.
    # The 8088 pays nothing measurable: br_docmap's one test is the test it
    # always made ([br_docfar] is [br_docems] OR kern_mega), a line record is
    # an OFFSET now and so cheaper on every kernel, and the regrow/remap sites
    # pay a compare. +366 bytes of image (48,035), +505 of BROWSER.O88 on disk
