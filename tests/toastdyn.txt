# tests/toastdyn.txt - the toast arguments that are BUILT AT RUN TIME
#
# Every fixed toast message is a TOASTSTR (or a TOASTRUN..TOASTEND run), and
# the assembler measures it against TOAST_MAX where it is written (SPEC.md
# 59.10). tests/unit/t_toast.py follows every toast argument back to where it
# was made, and fails on anything that is not one of those - unless it is a
# value only the running program knows: a name the user chose, a number, a
# line composed in a buffer, a C caller's argument. Those are this file.
#
# ONE LINE PER SOURCE: <path> <proc> <what>  # <why>
#   <proc> is the routine (or, for a buffer, the buffer) t_toast.py names,
#   <what> the instruction or `buffer`, exactly as its failure message prints
#   it - copy the suggested line and write the reason.
# A line `<path> <label> cut  # <why>` stops the walk at a label's entry, for
# a path no build can take; it needs a reason as good as any other line.
#
# The reason says what makes the text and what bounds it. A buffer of 25
# bytes or fewer is bounded by its own size; a longer one is bounded by what
# is composed into it, and the toast's own truncation is what the remainder
# is FOR - the name goes LAST (SPEC.md 59.10), so what is cut is the user's
# own word and not the program's.
#
# A RATCHET: a line no walk reaches any more fails the build. Shorter is
# better - a fixed string registered here is a string nobody measures.
