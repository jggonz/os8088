# tests/textsites.txt - the transparent-text registry (SPEC.md 6.6.3)
#
# `font_run` (SPEC.md 6.1) draws a cell's background and its glyph in ONE pass.
# The calls counted here are TRANSPARENT: they leave whatever is underneath, so
# a caller that fills a rect and then letters it writes every pixel twice, and
# on a 4.77MHz 8088 the gap between the passes is VISIBLE.
#
# ONE LINE PER FILE: <count> <path>  # <reason>
#
# A file NOT in this list may not call transparent text at all - that is the
# case that matters, because it is what a new package hits. A file in it may
# not exceed its count, and may not fall below it either: lowering the number
# after a conversion is the diff saying the work happened.
#
# The reason is not decoration. It is either one of SPEC.md 6.6.2's SIX cases
# - say WHICH - or the word `backlog:` and what it should become. "It was
# shorter to write" is not a reason, and neither is "the background is white
# anyway": a white background is a background, so fill it with the run.
#
# THIS IS A RATCHET, NOT A CLEAN GATE. It starts at the count the tree has,
# because a rule that cannot be enforced from the day it is written is not
# enforced at all. docs/TEXT-PLAN.md 4 is the order to work it down in.
#
# STAGE 4 IS FINISHED (SPEC.md 6.6.5, docs/TEXT-PLAN.md 4.4). Every line below
# now carries a REASON. FOUR still say `backlog:` and not one of the four is a
# conversion waiting to be typed: wm_draw_title's compose-and-blit answer has
# SHIPPED and the line left is its fallback, Arkanoid's capsule letter is a
# sprite (TEXT-PLAN 3.1), kernel/bootprof.inc is a surface no shipping build
# draws, and the Tracker's tui_runc is a measured cost trade whose fix belongs
# in font_run. A NEW backlog line is a claim that somebody is going to do it.
